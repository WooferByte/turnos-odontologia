# Tasks: infraestructura-postgresql

**Tamaño.** Este change tiene **28 tareas en 8 grupos**, frente a «alrededor de 20» de `CHANGES.md`. No hay una excepción registrada para C-02: queda como pregunta abierta para el autor en `design.md` («Open Questions»), con el motivo y qué se podría sacar.

Reglas de trabajo para todos los grupos (no son tareas):

- **Gobernanza ALTO.** No se empieza hasta que el autor apruebe `proposal.md`, `design.md` y este archivo.
- **TDD estricto.** El test que falla (RED) va antes que el código (GREEN). Un grupo termina con la suite por defecto en verde (`python -m pytest`, desde `backend/`) y, desde el grupo 2, también con el perfil (`python -m pytest -m postgres`).
- **El RED de un test del perfil `postgres` se demuestra con PostgreSQL levantado.** Un test omitido no es un RED. Si Docker Desktop no está en ejecución, el Apply frena y avisa (design I15).
- **Si un test nace verde**: no se da por bueno. Se rompe a propósito la línea de producción que debería protegerlo, se comprueba que falla, se restaura y se anota en el resumen del grupo.
- **Sin mocks** de sesión ni de repositorio. Sin nada asíncrono. Datos ficticios de `tests/factories.py` (RN-PR-01).
- **La suite por defecto no cambia de naturaleza**: sigue con SQLite en memoria, engine por test y `create_all`. No se toca ningún test existente.
- **Nombres, SQL y contenidos**: los de `design.md` (I1 a I16). Si falta algo, no se inventa: se vuelve al design. Si falla una verificación V1 a V14, se frena y se avisa al autor.
- **Versiones**: solo las de design I2. No se agrega ni se cambia ninguna otra.
- **Commits**: solo con el ok del autor (regla dura 10; criterio en design I16), en español y con prefijo.
- Rutas relativas a `backend/` salvo que se indique otra cosa. Los horarios de los tests son UTC, del día de prueba de `tests/conftest.py`.
